# threat-detection-engine-go

本地流式威胁检测与告警关联引擎：从本地规则文件加载检测规则，消费本地 JSONL
事件流（模拟安全日志），在事件时间滑动窗口内做关联检测，并对重复触发做告警
抑制与合并。乱序事件、规则热更新、重复触发场景下检测结论保持一致且可解释。

## 目录结构

- `internal/rules` — 规则加载、严格校验、原子热更新
- `internal/engine` — 事件时间滑动窗口关联、迟到事件处理、告警抑制合并、状态回收
- `cmd/detector` — 本地验证入口（CLI）
- `examples/` — 示例规则与示例事件流

## 规则格式

规则文件为 JSON，顶层只有一个 `rules` 数组。每条规则字段如下，**不允许出现
未定义字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 规则唯一标识，重复即整文件拒绝 |
| `version` | int | 规则版本号（正整数），告警可追溯该版本 |
| `name` | string | 规则名称 |
| `description` | string | 可选描述 |
| `severity` | string | `low` / `medium` / `high` / `critical` |
| `event_type` | string | 只关联该类型的事件 |
| `field_equals` | object | 可选，事件 `fields` 需全部等值匹配 |
| `window_seconds` | int | 滑动窗口长度（按事件时间） |
| `threshold` | int | 窗口内匹配事件数达到该值即触发 |
| `suppress_seconds` | int | 同规则同实体的告警合并窗口，0 表示不合并 |

### 严格校验与原子热更新

- 任何一条规则非法，**整个文件被拒绝**，绝不静默跳过部分规则。
- 拒绝原因以错误码区分：`INVALID_JSON`（文件级 JSON 错误）、
  `UNKNOWN_FIELD`（未知字段，精确到字段名）、`DUPLICATE_ID`（规则 ID 重复）、
  `INVALID_FIELD`（字段取值非法，逐条报告）。
- `rules.Loader` 通过原子指针切换规则集：更新要么整体生效，要么整体失败并
  **保留旧规则继续工作**，不会出现新旧规则混用。被删除规则的运行状态会被
  清理；保留规则的窗口状态在热更新后继续有效。

## 窗口与迟到语义

- 窗口归属只由**事件时间**（`timestamp`）决定，与到达顺序无关。
- 引擎维护水位线（已接受事件的最大事件时间）。事件时间早于
  `水位线 - allowedLateness` 的事件被视为**超出容忍的迟到事件**：明确拒绝并
  记录到 `LateEvents()`（含原因与当时水位线），不会悄悄丢弃；容忍范围内的
  迟到事件会被接受并正确改变检测结论。
- 触发是事件集合的纯函数：窗口 `(t-W, t]` 内匹配事件数首次达到阈值时在事件
  时间 `t` 触发。因此同一事件流（含乱序）重放得到**完全相同的告警**。
- `event_id` 重复投递会被去重；并发摄入有互斥保护，不重报不漏报。
- 过期状态（早于 `水位线 - 窗口 - 容忍度`）会被及时回收，长时间运行内存
  有界，不随事件量无界增长。

## 告警抑制与合并

- 同一规则在同一实体上的重复触发，若触发时间与已合并触发链的间隔在
  `suppress_seconds` 内，则合并为**一条带 `count` 次数的告警**；该语义定义在
  触发时间集合上（连通分量），与事件到达顺序无关。
- 不同规则、不同实体之间互不影响，绝不互相吞并。
- 每条告警都可解释：`rule_id` / `rule_version` 标识命中的规则与版本，
  `event_ids` 列出全部触发事件，`first_at` / `last_at` 给出触发时间范围，
  `count` 为合并的触发次数。告警 ID 由规则、实体与首次触发时间确定性生成。

## 事件格式

事件流为 JSONL（每行一个事件）：

```json
{"event_id":"e001","event_type":"login_failed","timestamp":"2026-10-05T12:00:00Z","entity":"alice","fields":{"source_ip":"10.0.0.9"}}
```

## 本地验证

```bash
# 运行示例（含乱序事件 e002 与超容忍迟到事件 e010）
go run ./cmd/detector

# 指定规则/事件流/容忍度，并在消费 5 条事件后热更新规则
go run ./cmd/detector -rules examples/rules.json -events examples/events.jsonl \
    -lateness 30s -reload examples/rules.json -reload-at 5

# 运行全部单测（日志标注了每个用例覆盖的业务场景）
go test -v ./...
```

`go test -v ./...` 的日志按业务分组：规则加载与校验（合法加载、重复 ID、
未知字段、非法取值、JSON 错误）、规则热更新（原子生效、失败保留旧规则）、
乱序事件（重放确定性、容忍内迟到生效、超容忍迟到标记）、告警抑制与合并
（同规则同实体合并、跨规则/跨实体不吞并）、并发写入（去重、不漏不重）、
窗口状态回收（内存有界）。
